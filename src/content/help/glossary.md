| Term | Meaning |
|---|---|
| **ACH** | A bank-to-bank transfer (the “Automated Clearing House”). Used for some gifts and many bills. Takes a few days |
| **Admin** | The role with full access, including roles and deletion |
| **Allocation** | The part of a payment credited to a pledge |
| **Anonymous / non-member payment** | A gift recorded without a member record: a visitor, organization or anonymous donor |
| **Auto / auto-reconciled** | A bank line the application matched by itself; can be undone |
| **Bank-confirmed** | A payment whose bank line has been linked to it |
| **Benevity** | The company that runs many employers’ giving and matching programs |
| **CSV** | A spreadsheet-like text file. Chase and Benevity provide them |
| **Dependent** | A spouse, child or relative in a household, attached to the head of household |
| **Deployment / deploy** | Putting a new version of the application online |
| **Dues (membership dues)** | The yearly membership contribution, based on the member’s **Yearly Pledge** |
| **Duplicate** | The same money, or the same person, recorded twice |
| **Employer match** | Money the member’s employer adds to the member’s gift. Never on the member’s tax statement |
| **Firebase** | Google’s service that hosts the website and handles phone sign-in |
| **For year / Applies to year** | Which year’s dues a dues payment pays for, when not the year it was paid |
| **GL code** | General-ledger code: the accounting category (INC… for income, EXP… for expenses) |
| **Head of household** | The member a household’s dues and statement belong to |
| **Ledger / ledger entry** | The accounting record. Every payment and expense has one |
| **Learned / remembered sender** | A sender the application has been told belongs to a member, used for suggestions |
| **Link** | Connecting a bank line to a payment that already exists, instead of creating a new one |
| **Live drive** | A pledge drive that is active and whose dates include today |
| **Mark Reconciled** | Sets a bank line aside as explained, without recording anything |
| **Member loan** | Money a member lent the church. A debt, not a gift |
| **MATCHED / PENDING / RECONCILED** | Bank line statuses: linked to one record / not yet handled / explained without a link |
| **OTP** | One-time password: the sign-in code sent by text |
| **Payer** | The name on the bank or Zelle side, which may differ from the member |
| **Pledge / pledge drive** | A promise to give during a fundraising campaign |
| **Receipt number** | The number from the paper receipt book. Required and unique for cash and checks (`000` = no receipt) |
| **Reconciliation** | Checking the books against the bank, line by line |
| **Role** | What a person may see and do in the application |
| **Square** | The company behind the church’s in-person card reader |
| **Stripe** | The company that processes online card and ACH payments |
| **Supabase** | The company hosting the database |
| **Transaction** | One recorded payment |
| **Webhook** | A secure automatic message from a service (Stripe, Square) telling the application something happened |
| **Zelle** | Bank-to-bank instant payments; the church receives them to its Zelle email |
| **Zelle Review** | The screen where Zelle notification emails are matched to members |
